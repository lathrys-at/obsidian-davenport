# A-11 — processFrontMatter byte determinism

This protocol produces the recorded fact for Appendix A item 11 of the
design spec. The test plan states the item and its branch in Part 6.1.

## Question

Does `processFrontMatter` write identical bytes for identical inputs in
every environment? An environment is one Obsidian API version on one
platform. Every device applies every inbound change to the same note —
the note that a record links — so the sync design depends on the answer
(spec §5.4).

## Procedure

1. Build the probe kit one time, from the repository root: `npm ci`,
   then `npm run probe:build`. Use the Node version that `.nvmrc` pins.
   The kit and its usage live in
   [`tools/a11-probe/`](../../../tools/a11-probe/README.md).
2. In each environment, install the probe plugin into a scratch vault.
   Then run the command **Run frontmatter probe**. The probe writes the
   file `frontmatter-probe/emission-samples-<timestamp>Z.json` into the
   vault.
3. Collect one results file from each environment. Compare the files:
   `node tools/a11-probe/compare.mjs <file> <file> ...`.

## Matrix

The minimum matrix is the current Obsidian API version on macOS. The
owner ruled that a previous-version cell is not required; issue #11
records the ruling. Verification runs forward instead: re-verify at
each Obsidian minor release, as [`facts.md`](../facts.md) directs. The
probe records the API version, because the typed API does not expose
the application version. Add platforms and versions when they are
available.

## How to read the comparison

- The corpus holds one control fixture and a set of parseable fixtures.
  The comparison reports one line per fixture.
- The word `agree` on a fixture line means that every environment
  emitted the same bytes for that fixture. The comparison proves the
  agreement with one hash for the group.
- The fixture `unparseable` is a control. In a correct run, every
  environment refuses this fixture. The comparison does not compare the
  wording of the errors, and the wording is not evidence.
- Determinism holds when every parseable fixture agrees across every
  environment, every environment refuses the control, and the run
  reports no cautions. A cautioned sample is not evidence about the
  writer, as the kit README states.

## Branch

- Determinism holds: record the fact. The result validates the [E]/[M]
  fakes of the test harness — the fakes that stand in for Obsidian's
  metadata and vault APIs.
- Determinism fails: the designated-writer redesign is necessary before
  stage 2. That redesign reintroduces per-device asymmetry into a system
  that is built on every-device symmetry, as Appendix A item 11 sizes
  it. The design change goes to the design spec, and not to the fact
  record.
